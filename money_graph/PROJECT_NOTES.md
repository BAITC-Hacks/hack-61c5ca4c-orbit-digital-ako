# Project notes — «Граф денег»

## Цель

Помочь финансовому аналитику быстро исследовать транзакционную сеть: увидеть, какие счета связывают части графа, где сходятся переводы и какие узлы стоит проверить первыми. Результат системы — приоритизированные гипотезы для ручной проверки, а не автоматическое обвинение клиента.

## Что показывает прототип

- Направленные связи между узлами с суммой и количеством транзакций.
- Метрики входящих и исходящих переводов, посредничества и достижимости от seed-клиентов.
- Ролевые гипотезы с числовым объяснением в `evidence`.
- Кластеры сети и список узлов для приоритетной проверки.
- Узлы на границе выгрузки отдельно помечаются как неполные наблюдения: отсутствие исходящих в данных не доказывает, что деньги остались на счёте.

## Поток обработки

1. Прочитать `nodes.parquet`, `edges.parquet` и `transactions.parquet`.
2. Построить направленный граф и вычислить структурные и временные признаки.
3. Оценить связи с seed-клиентами и приоритет узлов.
4. Назначить роли по прозрачным правилам и сформировать объяснения.
5. Сохранить таблицы анализа и офлайн-визуализацию.

Запуск из каталога `money_graph`:

```bash
pip install -r requirements.txt
python run.py
```

Основной экран после запуска: `out/viewer.html`.

## Как интерпретировать результаты

- Высокий приоритет означает «проверить раньше», а не «виновен».
- `truncated` означает, что сбор данных закончился на этом хопе; это не роль конечного получателя.
- `pass_through` рассчитывается только по суммам, видимым в текущей выгрузке. Для seed-клиентов входящие могут быть неполными.
- Объём «меченого потока» — оценка по наблюдаемым рёбрам. При последовательных переводах одна и та же сумма может учитываться на нескольких этапах.
- Кластеры построены на неориентированной проекции для поиска плотных связей; направление переводов используется в других метриках.

## Перед финальной сдачей

- Сверить допустимые значения поля `role` с актуальным формальным ТЗ. Сейчас код использует дополнительное значение `truncated`; если схема допускает только роли из стартового шаблона, потребуется согласовать или преобразовать его.
- Убедиться, что выгрузки находятся в ожидаемом платформой месте и имеют обязательные имена и колонки.
- В демо объяснять каждый вывод через наблюдаемые признаки и явно проговаривать неполноту данных.

## Распределение работы команды

- Аналитика: проверить допущения, пороги и объяснимость ролей.
- Приложение: запуск пайплайна, интерфейс графа и удобство поиска узлов.
- Демонстрация: сценарий показа, ограничения модели и ответы на вопросы жюри.
