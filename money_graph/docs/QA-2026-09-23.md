# Проверка рабочего места AML-аналитика · 23 сентября 2026

Проверена локальная веб-система и воспроизводимый расчёт на данных кейса.

## Проверено

- Полный пересчёт: 2 248 клиентов, 3 119 связей, 4 840 транзакций, 71 кластер; около 4,6 секунды без времени импорта зависимостей.
- 15 тестов pytest проходят, включая типы сумм и сохранение заявленной границы обхода.
- Загрузка валидного кейса возвращает 201; граф и все пять CSV-выгрузок доступны.
- Некорректный Parquet отклоняется с 422; временные файлы ошибочного кейса очищаются.
- Чужой Host отклоняется с 400, загрузка с чужим Origin — с 403, неизвестные кейсы и имена выгрузок — с 404.
- Gid передаются в интерфейс строками, без потери точности длинных идентификаторов.
- Веб-интерфейс проверен на ширинах 320, 390, 828 и 1440 px: без горизонтального переполнения, область графа имеет ограниченную высоту.
- Проверены поиск конкретного gid, карточка, видимый направленный граф и разворачивание схемы. Ошибок JavaScript при проверке не обнаружено.

## Исправления интерфейса

Обоснования показываются полностью шрифтом 15 px, отдельно от индекса приоритета. Сводка объясняет смысл клиентов, seed, переводов и кластеров. Добавлены навигация по сценарию аналитика, подписи периода и порога, постоянная легенда ролей. На узком экране граф расположен перед очередью проверки. Высота списка больше не растягивает canvas на тысячи пикселей.

Сохранены функции параллельного обновления команды: просмотр переводов по связи, страницы списков, масштабирование, разворот графа, проверка глубины выгрузки и числовых типов сумм.

## Что остаётся перед финальной сдачей

1. **Словарь обязательной колонки role.** В 444 строках используется `truncated`. Дополнительная `role_base` содержит шесть базовых значений, но не подменяет `role` для внешнего валидатора. Если ТЗ допускает только базовый словарь, нужен строгий экспорт: базовая роль в `role`, признак обрезки — в отдельном поле. Наши существующие тесты явно разрешают расширение и не доказывают прохождение неизвестного валидатора жюри.
2. **Ресурсные ограничения загрузки.** Лимит 64 МБ проверяется после разбора multipart. Нужны ограничение всего HTTP-тела до разбора, лимиты строк/узлов после чтения метаданных Parquet и ограничение параллельных расчётов. Нагрузочные атаки не выполнялись. Поведение multipart описано в [документации Starlette](https://www.starlette.io/requests/).
3. **Воспроизводимость установки.** В requirements заданы нижние границы версий. На проверяемом Windows-компьютере новая SciPy блокировалась Application Control; запуск выполнен с уже установленной совместимой SciPy 1.17.1. Настройки защиты ОС не менялись. Для сдачи рекомендуется зафиксировать проверенные версии зависимостей. В проверенном наборе зависимостей приложения pip-audit не нашёл известных уязвимостей; это не полноценный пентест.

## Полезные следующие функции

- Список «На углублённую проверку»: ручной выбор клиентов, заметка аналитика, экспорт обоснований.
- Фильтр периода и временная цепочка переводов выбранного клиента.
- Строгий пакет сдачи: обязательные CSV, краткий отчёт и параметры расчёта в одном архиве.
