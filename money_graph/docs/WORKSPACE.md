# Личная рабочая область кейса

Модуль `workspace_api.py` предоставляет документы, неизменяемые отчёты и локальный поиск оснований. Этот модуль не отправляет данные во внешние AI/API. Ответ поиска прямо сообщает: «Ответ НЕ сгенерирован LLM». Отдельная панель «Разобрать узлы и связи» поддерживает вопросы к OpenAI по выбранным счетам; личные TXT/MD в её инструменты не входят.

## Подключение

```python
from workspace_api import install_workspace_routes

install_workspace_routes(app, resolve_case, ROOT / ".local" / "workspaces")
```

Хост предоставляет синхронный `resolve_case(request, case_id) -> (dataPath, outPath, label)` и middleware с `request.state.user = {"id": UUID, "username": str, "role": str}`. Каждый обработчик сначала вызывает `resolve_case`, включая запросы с неверным телом, идентификатором документа/отчёта или форматом. Проверка владения кейсом, вход, глобальный CSRF и общие HTTP-заголовки остаются в хосте. Роль `admin` открывает только метаданные `/developer`; она не открывает документы и отчёты других пользователей.

Хранение: `storage_root/{user_id}/{case_id}/state.json`, где UUID пользователя приводится к стандартной записи с дефисами. В одном атомарно заменяемом JSON находятся документы, снимки отчётов и история. Общий процессный lock и файловый lock ОС защищают конкурентные изменения, в том числе между локальными worker-процессами. Запись сначала сбрасывается в временный файл через `fsync`, затем выполняется `os.replace`; ошибка до замены сохраняет прежнее состояние. Ссылки/junctions в пользовательских путях отвергаются. Исходное имя и путь загруженного файла не сохраняются. Аутентифицированные HTTP-маршруты обеспечивают изоляцию; это не шифрование файлов от администратора ОС.

При сравнении уже разрешённых путей Windows формы `\\?\C:\...` и `C:\...` (а также обычная/расширенная UNC-запись) приводятся к одной форме. `Path.resolve()` может вернуть разные формы при одновременном создании пользовательской папки; нормализация устраняет ложный 404. Проверки владельца, ссылок/junctions и выхода за корень остаются обязательными. Другие пространства имён Windows не нормализуются.

## Контракт для frontend / main

Базовый путь: `/api/cases/{case_id}`. Все GET-списки — **обычные JSON-массивы**, без `items`. Документ POST и отчёт POST возвращают один объект метаданных, статус `201`.

| Метод и путь | Вход | Успешный ответ |
| --- | --- | --- |
| `GET /documents` | — | `[{id,title,created_at}]` |
| `POST /documents` | multipart: один `file`; необязательный `title` | `{id,title,created_at}` |
| `DELETE /documents/{doc_id}` | — | `{id,deleted:true}` |
| `GET /reports` | — | `[{id,title,version,created_at,selected_gids}]` |
| `POST /reports` | JSON `{title,selected_gids,notes}` | `{id,title,version,created_at,selected_gids}` |
| `GET /reports/{report_id}/download?format=html\|md\|json` | формат по умолчанию `html` | файл с `Content-Disposition: attachment` |
| `GET /reports/{report_id}/view` | — | тот же HTML с `Content-Disposition: inline`, для новой вкладки и Ctrl+P |
| `GET /audit` | — | массив записей истории (ниже) |
| `POST /ask` | JSON `{question}` | `{answer,mode,sources,diagnostics}` (ниже) |
| `GET /developer` | роль `admin` | безопасные метаданные метода и лимитов |

`id` документа, отчёта и события — случайные 32-символьные UUID hex. `created_at` — ISO 8601 в UTC с суффиксом `Z`. `selected_gids` всегда массив **строк**, включая полные 18–19-значные идентификаторы. Нельзя преобразовывать их в JavaScript Number. Версия отчёта последовательно возрастает с 1 отдельно для каждой пары пользователь/кейс. Создание новой версии требует нового POST; обновления и удаления отчётов нет.

Объект `/audit`:

```json
{
  "id": "<uuid-hex>",
  "sequence": 1,
  "action": "report.created",
  "created_at": "2026-09-23T12:00:00.000000Z",
  "author": {"id": "<user-uuid>", "username": "Аналитик"},
  "resource_id": "<report-or-document-id>",
  "title": "Проверка переводов",
  "version": 1
}
```

Действия: `document.created`, `document.deleted`, `report.created`; у документов `version: null`. История содержит изменения, не чтения/поиск/скачивание. Событие и само изменение сохраняются одним атомарным обновлением. История приложения не является криптографически защищённым журналом.

Объект `/ask`:

```json
{
  "answer": "Локальный поиск по документам и метрикам. Ответ НЕ сгенерирован LLM.\nНайденные основания: 2 из 2 источников. Фрагменты приведены ниже.",
  "mode": "local-evidence",
  "sources": [
    {
      "id": "top:100000003684369100:1",
      "title": "Приоритетная проверка · GID 100000003684369100",
      "excerpt": "GID: 100000003684369100\nРоль: Координатор\nПриоритет проверки: 0.9900\nОснования: ...",
      "kind": "top_nodes"
    }
  ],
  "diagnostics": {
    "method": "Лексический поиск без учёта регистра; для точного GID сначала why из списка приоритетов; один лучший фрагмент на источник.",
    "llm_connected": false,
    "external_requests": false,
    "query_terms": ["100000003684369100"],
    "documents_searched": 0,
    "nodes_searched": 2,
    "top_rows_searched": 1,
    "chunks_searched": 3,
    "matches": 2,
    "returned": 2,
    "max_sources": 8,
    "truncated": false
  }
}
```

Виды источников: `node`, `top_nodes`, `document`. Формат `id`: `node:{gid}:{chunk}`, `top:{gid}:{chunk}`, `document:{doc_id}:{chunk}`, номера фрагментов с 1. Это ссылки на основания, а не файловые пути/URL. `answer` содержит только короткий статус режима и количество найденных источников; фрагменты находятся только в `sources`. Для каждой строки CSV или документа возвращается не более одного лучшего фрагмента. Ответ и excerpt — обычный текст, **в UI отображать через `textContent`**, включая похожие на HTML фрагменты; не использовать `innerHTML` и не исполнять Markdown. Содержимое документов не управляет программой и не попадает в системные инструкции модели.

`GET /developer` возвращает `{mode,method,llm_connected,external_requests,sources,limits,disclaimer}`. Не раскрывает абсолютные пути, переменные окружения, ключи, чужие документы или внутренние исключения. `limits` содержит `document_bytes`, `documents`, `document_total_bytes`, `reports`, `report_nodes`, `neighbours`, `report_links`, `drawn_links`, `retrieval_sources`.

## Отчёты и источники

Снимок сохраняет `schema_version`, `id`, `title`, `version`, `case_id`, `label`, `created_at`, `author:{id,username}`, `selected_gids`, `notes`, `method`, `nodes`, `network`, `sources`, `warnings`. `/download?format=json` возвращает весь снимок. Последующие изменения CSV, заметок в новых отчётах и удаление документов не меняют существующий отчёт. Личные документы используются в поиске; CSV-отчёт не включает их содержимое.

Каждый элемент `nodes` содержит `{gid,selected,role_description,metrics,top}`. `metrics` — все исходные поля строки `nodes_roles.csv`; `top` — все поля строки `top_nodes.csv` или `null`. Значения CSV сохранены строками, без округления сумм, сокращения GID или пересчёта `evidence`/`why`. Для описания роли используется `role_detail`, если он заполнен, иначе `role`. `truncated` или истинный `is_truncated` дают пояснение «Обрезан на границе выгрузки: дальнейшее движение средств неизвестно»; поле `role` из строгого словаря также остаётся в таблице без изменения.

`network` содержит `nodes:[gid]`, `links:[{src,dst,sum_kzt,n_tx}]`, `source`, `adjacent_links_total`, `included_links`, `omitted_links`, `drawn_links`. Источник связей — `dataPath/edges.parquet`; для небольших локальных наборов допустим `edges.csv`. Для parquet берутся четыре указанных столбца; CSV сохраняет также дополнительные столбцы. Таблица связей в HTML/MD показывает GID отправителя и получателя, сумму KZT и количество операций. Если таблица отсутствует, снимок явно сообщает об этом и не выдумывает связи.

В отчёте максимум 30 узлов всего: выбранные и до пяти соседей. Сначала учитываются связи между выбранными узлами, затем связи по убыванию суммы; при равенстве — по GID. Включается до 1000 связей, соприкасающихся с выбранными узлами и имеющих оба конца среди включённых узлов. Пропуски явно посчитаны в `omitted_links`. SVG показывает первые 120 связей; остальные включённые связи остаются в таблице. Схема поддерживает направление, встречные связи и петли. Для графика используется детерминированная круговая раскладка, без библиотек из сети.

HTML — самостоятельный экранированный документ с CSP, встроенными CSS/SVG и печатным стилем. Сначала показываются выбранные клиенты: понятная роль, исходное `why` и `evidence`, пять ключевых метрик (приоритет, входящие/исходящие KZT, число отправителей/получателей). Соседи сведены в одну компактную таблицу с основанием до 240 символов. Далее идут небольшая направленная схема и таблица связей. Принудительных разрывов страницы для каждого клиента нет; полные исходные поля доступны в JSON и MD. Суммы ключевых метрик сохраняются без округления.

Нет JavaScript, внешних ресурсов, исполняемого HTML из документов или сети. `/view` открывает HTML в браузере с проверкой кейса и владельца отчёта; подходит для frontend-ссылки «Открыть / PDF» в новой вкладке. Ctrl+P позволяет распечатать или сохранить PDF. `/download` по-прежнему возвращает вложение; содержимое HTML одинаково в обоих маршрутах. MD также экранирует сырой HTML и Markdown-управляющие символы; JSON сохраняет исходные значения как данные. Название не входит в HTTP-имя файла: используется безопасное `report-{id}-v{version}.{format}`.

## Метод поиска и ограничения

При каждом поиске читаются текущие `outPath/top_nodes.csv`, `outPath/nodes_roles.csv` и только документы текущего пользователя в текущем кейсе. По каждой CSV-строке формируется краткое основание с русскими подписями: GID, роль, приоритет, исходное объяснение `why`/`evidence`, доступные ключевые метрики. Технический перечень всех raw-полей не попадает в UI-поиск; он сохраняется в JSON/MD отчётов. Документы используются как буквальный текст. Нормализация: NFC, регистр, `ё → е`; базовые русские служебные слова исключаются, до 32 уникальных слов запроса. Нет морфологии, embeddings, семантического поиска или выводов о фактах, которых нет в тексте.

Окно excerpt — до 800 символов, шаг 600; дополнительного хвостового фрагмента после полного покрытия текста нет. Счёт равен `100 * число различных совпавших слов + сумма min(частота слова, 10)`. Учитываются заголовок и excerpt. Внутри ресурса выбирается один фрагмент с максимальным счётом, при равенстве — самый ранний. При точном GID в вопросе сначала идёт его `top_nodes` с `why`, затем его `node`, затем остальные совпадения. Далее сортировка по счёту и `id`; выдаётся до восьми разных ресурсов. `diagnostics.matches` — количество подходящих ресурсов, `chunks_searched` — количество проверенных фрагментов. Пустая выдача прямо сообщает, что совпадения не найдены и отсутствие совпадения не доказывает отсутствие факта. На вопрос о RAG добавляется пояснение готовности локального поиска и отсутствия подключённой генеративной модели. Никакие инструкции из источников не выполняются.

Лимиты MVP:

- Документ: `.txt`/`.md`, корректный UTF-8, непустой, до 2 МиБ включительно; BOM допустим. Нулевые/двоичные управляющие символы запрещены. Имя используется только для безопасного отображаемого заголовка, путь отбрасывается; заголовок нормализуется и сокращается до 120 символов. Необязательный входной `title` — до 240 символов.
- До 50 документов и 20 МиБ исходного текста суммарно на пользователя/кейс.
- Отчёт: непустой `title` до 120 символов; `notes` до 5000 символов, по умолчанию пустая строка; 1–30 различных `selected_gids`, каждый строка вида `-?\d{1,19}` и существующий GID текущего кейса. Неизвестный/невалидный GID даёт 422.
- До 100 неизменяемых отчётов; до 5000 событий; состояние до 64 МиБ. Лимит возвращает понятную ошибку, без удаления предыдущих версий.
- Вопрос: непустая строка до 2000 символов. JSON-запрос до 128 КиБ; неизвестные поля отклоняются.
- Полное multipart-тело ограничено 2 МиБ + 64 КиБ до разбора; сам файл отдельно проверяется на 2 МиБ.
- Каждая исходная таблица до 32 МиБ и 100000 строк, CSV до 128 столбцов, одно значение до 8192 символов. Оригинальные CSV и parquet должны быть опубликованы хостом как готовые результаты анализа; одновременная перезапись исходных таблиц анализатором не образует транзакцию с созданием отчёта.

Ошибки JSON в формате FastAPI `{detail: "сообщение"}`: `401` — нет пользователя; `403` — developer не для admin; `404` — неизвестный/чужой объект либо недоступный кейс; `409` — лимит рабочей области или некорректные/неготовые таблицы; `413` — размер; `415` — неверный Content-Type; `422` — поля/формат; `503` — занятое/нечитаемое состояние. Проверка владения кейсом выполняется до этих проверок тела.

## Проверка

Из корня репозитория:

```powershell
& money_graph/.local/venv/Scripts/python.exe -m pytest -q tests/test_workspace_api.py
```

Тесты используют маленькие искусственные CSV и отдельные временные пользовательские хранилища. Проверяются сохранение после повторного подключения приложения, неизменяемость исходных метрик, экранирование HTML/MD, направленный SVG, версии и атомарность, личные документы/отчёты/история, 404, неверные GID, порядок ownership-проверок во всех маршрутах, UTF-8/лимиты, prompt injection как данные, детерминированная выдача, новый словарь ролей, граница выгрузки и чтение реальных parquet-типов GID без потери точности.
