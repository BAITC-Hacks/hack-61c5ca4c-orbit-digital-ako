# Локальная многопользовательская платформа

## Первый вход

Из `money_graph` установите `requirements.txt`, выполните `python manage_users.py bootstrap --username admin`, затем запустите `python -m uvicorn server:app --host 127.0.0.1 --port 8765`. Временный пароль находится в `.local/admin-onboarding.txt`. Смените его при первом входе, после чего удалите этот файл. Bootstrap не перезаписывает существующих пользователей. Восстановление доступа выполняется локально через `python manage_users.py reset --username admin` с вводом пароля без эха.

Администратор создаёт аналитиков во вкладке «Пользователи» и передаёт одноразово отображённый пароль лично. Аналитик обязан сменить его. Отключение пользователя отзывает его сессии; его материалы сохраняются. Открытой регистрации и анонимного доступа к данным нет.

## Границы доступа

- Загруженный кейс привязан к текущему пользователю на сервере. Переданный клиентом `owner_id` не влияет на владельца.
- Угаданный UUID не даёт доступа к графу, транзакциям, документам, отчётам или CSV. Постороннему возвращается 404, незалогиненному — 401.
- Администратор управляет аккаунтами, но не читает чужие кейсы через интерфейс.
- Только приложенный демо-набор общий для вошедших пользователей; личные материалы по нему разделены.
- Старые загрузки без `owner_id` закрыты для всех. Их нельзя автоматически присваивать первому вошедшему; миграция требует проверки владельца оператором.
- Пароли хранятся как scrypt-хеши с солью, токены сессий — как SHA-256-хеши. Cookie HttpOnly/SameSite=Strict; Secure включается на HTTPS. Изменения требуют CSRF-токена, чужой Origin отклоняется.
- Данные схемы не записываются в localStorage. При выходе рабочие данные очищаются из интерфейса.

Это изоляция через HTTP-приложение, **не защита от администратора операционной системы**. Файлы состояния не зашифрованы. `.local` исключена из Git, но это не заменяет настройки файловых прав и резервные копии.

## Рабочий процесс

1. Загрузить Parquet-кейс и проверить параметры выгрузки.
2. Выбрать клиента, раскрыть исходные переводы, проверить числовые основания.
3. Нажать «В отчёт» либо вручную выбрать стартовый топ-5 в разделе отчётов.
4. Добавить заметку и сохранить неизменяемую версию. Следующее сохранение создаёт новую версию, а не перезаписывает предыдущую.
5. Открыть/скачать HTML со схемой и таблицами; в браузере доступна печать в PDF. Markdown и JSON предназначены для дальнейшей обработки.

«Версии» — снимки отчётов и история действий, не отдельные Git-репозитории пользователей. Коммиты исходного кода команды выполняются отдельно. Скачанный файл содержит данные: его дальнейшая передача находится вне контроля платформы.

## Поиск / RAG

Документы TXT/MD сохраняются в личной рабочей области. Поиск сопоставляет слова вопроса с обоснованиями, метриками и документами текущего кейса и возвращает источники. Документы считаются данными, не инструкциями. PDF/DOCX и OCR не подключены.

Этот поиск работает локально без генеративной LLM. В отдельной панели «Разобрать узлы и связи» доступен помощник OpenAI: только кнопка «Спросить ИИ» отправляет вопрос и необходимые результаты инструментов по текущему кейсу. Личные TXT/MD в эти инструменты не входят. Для ИИ действуют те же проверки входа, владельца кейса и CSRF. При выходе вопрос, выбранные счета и ответ очищаются. Настройка API описана в [README](../README.md#помощник-по-выбранным-счетам).

## Ресурсные пределы MVP

Кейс: до 64 МиБ на каждый из трёх файлов; общий HTTP-лимит 193 МиБ. До чтения таблиц проверяются метаданные Parquet: 5 000 узлов, 20 000 связей, 200 000 транзакций, 64 колонки и 128 МиБ распакованных данных на таблицу. Одновременно выполняется один расчёт. Документ: до 2 МиБ, до 50 документов и 20 МиБ текста на личный кейс. Отчёт: до 30 выбранных клиентов; соседство и связи ограничены и явно помечены как частичные.

Для изолированных локальных запусков путь состояния задаётся `MONEYGRAPH_STATE_DIR`. CLI управления пользователями принимает соответствующий `--root <путь>` перед командой. Не выбирайте для состояния каталог публичной статики или Git.

## Перед реальным банковским внедрением

Нужны отдельный security review, HTTPS и сетевые ограничения, корпоративные SSO/MFA, политика хранения и удаления, шифрование/управление ключами, централизованный защищённый аудит, резервное копирование, квоты суммарного диска и нагрузочные испытания. Существующая история приложения не является криптографически защищённым аудитом. Содержимое проверяется в тестах, но это не аттестация безопасности и не гарантия отсутствия уязвимостей.
