## Автоматические проверки

- **80 Python-тестов:** исходная схема/валидатор, точные роли/поток/AUC/топ/устойчивость, единый trace, синтетические форматы, отсутствие дат и seed, качество, CSV-инъекции, полный API-жизненный цикл, кэш, блокировка/атрибуция, HTML-экранирование, удаление, отсутствие привязок к набору данных; существующие тесты ассистента и ошибок провайдера. API проверяет подтверждение передачи, отсутствие ключа, ссылки на строковые ID, валюту проекта, безопасную ошибку провайдера и экспорт выбранных строк.
- **4 Playwright-сценария:** демо→trace→блокировка→дело; собственный CSV+seed→mapping→USD→расчёт→дело; производительность/доступность/офлайн/тёмная тема; локальный ассистент→основания на графе→экспорт выбранных строк.
- Частичный поиск Ctrl+K и восстановление узла в новой вкладке проверены.
- Проверена мобильная ширина 420 px без горизонтального переполнения.
- После исправлений **axe: 0 нарушений** на восьми проверенных экранах в светлой теме, включая ответ ассистента. Это автоматическая проверка; отдельная ручная сертификация WCAG и экранными дикторами не проводилась.
- При работе приложения, включая Swagger, **0 внешних сетевых запросов** в браузерном аудите.
- `npm run build` проходит с TypeScript strict. Один vendor chunk около 548 КБ вызывает информационное предупреждение Vite; ресурсы локальные, основной код приложения выделен отдельно.

## Производительность

`syn_big`: **100 000 узлов, 300 000 транзакций, 245,7 с** от чтения до результатов. Внедрённые консолидаторы — в топ-50. Основные этапы: метрики до ~143 с от начала, блокировка до ~170 с, роли до ~187 с, кластеры до ~231 с, устойчивость до ~246 с.

Sigma с 3 000 реальными узлами синтетического проекта: около **119–120 кадров/с** по requestAnimationFrame при перемещении камеры на этой машине. Это локальное измерение, а не обещание той же скорости на любом устройстве.

Главные ограничения: Python/NetworkX betweenness и Louvain, вычисление BFS от каждого seed, а на плотных циклических графах — поиск циклов. При иной структуре сети или большем числе seed время может быть выше. Крупные операции пока отменяются только между этапами.

## Убранные привязки

- Фиксированный месяц заменён min/max датами проекта.
- Валюта и порог сбора передаются из параметров; неизвестный порог не подставляется в текст.
- Граница обхода отделена от наблюдаемой/BFS-глубины.
- Интервал быстрого транзита берётся из конфигурации.
- ID в ядре и API строковые; нет потери точности в JavaScript.
- Нет обязательного наличия seed, дат или глубины; отсутствующие возможности явно объявлены.
- Вместо правила и отдельной имитации объяснения используется один набор условий.
- В `mg/`, `api/`, `web/src/` тестом проверено отсутствие запрещённых строк месяца, валюты, фиксированного порога/хопа и конкретных длинных идентификаторов. Валюта по умолчанию остаётся только в `config.json`.

## Практические границы MVP

- Досье — рабочий аналитический документ, не утверждённая ведомственная форма. Заголовки печатного шаблона пока русскоязычные; evidence следует языку расчёта.
- Экспорт результатов доступен по проекту и выбранным строкам таблицы. Массовые действия — дело, блокировка и CSV.
- Состояние раскладки/закрепления/выбора хранится в текущем браузере; URL переносит выбор узла и фильтры, но не все персональные настройки холста.
- Задачи не восстанавливаются после перезапуска сервера автоматически; завершённые расчёты и дела сохраняются.
- Нет многопользовательской аутентификации и шифрования проекта на уровне приложения. Для общего развёртывания требуется отдельная работа.
- Ассистент повторно использует `mg/assistant.py` и `mg/provider_errors.py` из `origin/main` (`ab08d0d`). Провайдер проверен тестовыми ответами, реальный внешний запрос не выполнялся: ключ не настроен. Данные не отправляются без подтверждения.
- Хронологическая модель и отдельные личные кабинеты из удалённой ветки не включены: сохранён явно требуемый числовой эталон. Полное слияние ветки не выполнялось; удалённые изменения не перезаписывались.
